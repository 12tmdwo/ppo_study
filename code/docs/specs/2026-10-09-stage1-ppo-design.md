## 한눈에 보기

### 1단계에서 하는 일
PPO라는 학습 방법을 코드로 직접 만들고, 제대로 만들었는지 수레-막대 예제로 시험한다.

전체 과정은 문제집을 푸는 것과 비슷하다. Claude가 문제집(빈칸이 뚫린 코드)과 채점기(검사 코드)를 만들면, 사용자가 빈칸을 채우고 채점을 받는다. 빈칸을 다 채우면 마지막으로 실제 시험(수레-막대 학습)을 본다.

### 누가 무엇을 하는가

| 순서 | Claude가 하는 일 | 사용자가 하는 일 |
|---|---|---|
| ① 준비 | 빈칸이 뚫린 코드, 채점기, 나머지 코드를 모두 만든다 | 없음 |
| ② 빈칸 채우기 | 빈칸마다 원리를 먼저 설명하고, 막히면 힌트를 준다 | 빈칸을 채우고 채점 명령을 실행한다 |
| ③ 시험 | 결과 그래프를 그리고, 결과를 함께 해석한다 | 학습 명령을 실행하고 점수를 확인한다 |

사용자가 직접 쓰는 코드는 빈칸 5개이며, 전부 합쳐서 50~60줄 정도이다.

### 빈칸 5개가 하는 일 (수레-막대 예제 기준)
1. **행동 뽑기 (2개)**: 신경망이 "오른쪽으로 0.3만큼 밀어라" 같은 값을 내놓으면, 여기에 약간의 무작위를 섞어서 실제 행동을 정한다. 무작위를 섞어야 새로운 행동을 시도해 볼 수 있다.
2. **이득 계산**: 16걸음 동안 받은 점수를 보고, 걸음마다 그때 한 행동이 평소보다 얼마나 좋았는지를 숫자로 계산한다.
3. **PPO 손실**: 좋았던 행동은 더 자주 하고 나빴던 행동은 덜 하도록, 신경망을 얼마나 수정할지 계산한다. 한 번에 너무 많이 바꾸면 학습이 망가지므로 수정하는 양을 제한한다.
4. **고치기 반복**: 위의 계산을 모아 둔 경험 전체에 여러 번 적용해서 실제로 신경망을 수정한다.

### 작업 한 번의 모습
1. `ppo/ppo.py`에서 빈칸 함수 하나를 찾는다. 함수 안에는 설명, 힌트, `raise NotImplementedError`가 들어 있다.
2. `raise NotImplementedError` 줄을 지우고 코드를 채운다.
3. 터미널에서 `pytest ppo/test_ppo.py -k gae`처럼 그 빈칸의 채점 명령을 실행한다.
4. 전부 PASSED가 나오면 다음 빈칸으로 넘어간다. FAILED가 나오면 어떤 검사가 틀렸는지 보고 다시 고친다.
5. 빈칸 5개를 다 채운 뒤 `python ppo/train.py --seed 1`로 학습시킨다. 점수가 4.5를 넘으면 통과이다.

## 5. 빈칸 함수 상세 (`ppo/ppo.py`)

표기: `N` = 동시에 도는 환경 수(4096), `T` = 한 번에 모으는 걸음 수(16), `A` = 행동 개수(수레-막대는 1)

빈칸마다 **입력·출력 모양 설명, 힌트, 수식**을 주석으로 달아두고, 함수 본문은 `raise NotImplementedError`로 비워둔다.

### 다. 행동 뽑기 (함수 2개)

```python
def sample_action(mean, std):
    """정규분포 N(mean, std)에서 행동을 뽑고, 그 행동의 로그 확률을 돌려준다.
    입력: mean (N, A), std (N, A) 또는 (A,)
    출력: action (N, A), log_prob (N,)   ← 행동 개수 방향으로 더한 값
    """

def evaluate_action(mean, std, action):
    """이미 뽑았던 행동이 지금 신경망 기준으로 나올 로그 확률과, 분포의 엔트로피(퍼짐 정도)를 돌려준다.
    출력: log_prob (N,), entropy (N,)
    """
```

핵심 수식은 다음과 같다. 행동 하나(`i`)마다 계산한 뒤 `A` 방향으로 더한다.
- 로그 확률: `log π(a) = −(a − μ)² / (2σ²) − log σ − ½·log(2π)`
- 엔트로피: `H = ½ + ½·log(2π) + log σ`

수식을 직접 쓰는 것을 권장한다. `torch.distributions.Normal`은 검사 코드에서 정답 비교용으로만 쓴다.

**검사 항목**
- 뽑은 행동 수만 개의 평균·표준편차가 `mean`, `std`와 맞는지
- 로그 확률과 엔트로피가 `torch.distributions.Normal` 결과와 같은지
- 출력 모양이 맞는지

### 라. 이득 계산 (GAE)

```python
def compute_gae(rewards, values, dones, last_values, gamma, lam):
    """입력: rewards (T, N), values (T, N), dones (T, N) (그 걸음에서 판이 끝났으면 1),
            last_values (N,) (마지막 걸음 다음 상태의 가치)
    출력: advantages (T, N), returns (T, N)
    """
```

핵심 수식은 다음과 같다. 마지막 걸음부터 `t = T−1 … 0` 순서로 거꾸로 계산한다.
- 다음 가치: `t = T−1`이면 `last_values`, 아니면 `values[t+1]`
- 오차: `δ_t = r_t + γ · V_next · (1 − done_t) − V_t`
- 이득: `A_t = δ_t + γ · λ · (1 − done_t) · A_{t+1}` (`A_T = 0`)
- 목표 가치: `returns = advantages + values`

**검사 항목**
- 손으로 계산한 3걸음짜리 예제와 정답 비교
- 판이 끝난 걸음(`done=1`) 너머의 점수가 섞이지 않는지
- `λ = 0`일 때 이득이 한 걸음 오차 `δ`와 같은지

### 마. PPO 손실

```python
def ppo_loss(new_log_prob, old_log_prob, advantages, new_values, returns, entropy,
             clip_param, value_coef, entropy_coef):
    """출력: loss (숫자 하나), info (dict: 정책 손실, 가치 손실, 엔트로피, KL, 잘린 비율)"""
```

핵심 수식은 다음과 같다.
- 확률 비율: `ratio = exp(new_log_prob − old_log_prob)`
- 정책 손실: `L_정책 = −평균( min(ratio·A, clip(ratio, 1−ε, 1+ε)·A) )`
- 가치 손실: `L_가치 = 평균( (new_values − returns)² )`
- 전체: `loss = L_정책 + value_coef · L_가치 − entropy_coef · 평균(entropy)`
- 학습 상태 확인용 지표 (기울기는 계산하지 않음)
  - 신경망이 바뀐 정도(KL 근사): `평균( (ratio − 1) − log(ratio) )`
  - 잘린 비율: `평균( |ratio − 1| > ε )`

**검사 항목**
- `ratio = 1`(신경망이 바뀌지 않음)이면 정책 손실이 `−평균(A)`와 같은지
- 비율이 `1+ε`를 넘고 이득이 양수일 때 정책 쪽 기울기가 0이 되는지 (= 잘림이 동작하는지)
- 이득이 음수일 때 반대 방향으로 잘리는지
- 엔트로피 항의 부호가 맞는지 (엔트로피가 클수록 손실이 작아야 함)

### 바. 고치기 반복

```python
def ppo_update(actor, critic, optimizer, batch, cfg):
    """batch: obs, actions, old_log_probs, advantages, returns (모두 T×N개를 한 줄로 편 것)
    cfg: 반복 횟수, 미니배치 수, ε, 계수들, 기울기 최대 크기
    출력: info (dict: 반복 전체 평균 손실·KL·잘린 비율 등)
    """
```

할 일
1. 이득을 배치 전체 기준으로 정규화 (평균 0, 표준편차 1)
2. `epochs`(5)번 반복: 순서를 섞어 `num_mini_batches`(4)개로 나누고, 각 조각마다
   - 정책·가치 신경망 계산 → `evaluate_action` → `ppo_loss`
   - 역전파 → 기울기 크기 자르기(`max_grad_norm`) → `optimizer.step()`
3. 학습 상태 지표의 평균을 계산해서 돌려주기

**검사 항목**
- 한 번의 반복에서 모든 데이터가 빠짐없이 한 번씩 쓰이는지
- 아주 쉬운 가짜 문제(좋은 행동이 정해진 문제)에서 몇 번 고치면 좋은 행동의 확률이 올라가는지
- 신경망 값이 실제로 바뀌는지

## 6. 전체 반복문 (`ppo/train.py`, Claude 작성)

```
시뮬레이터 켜기 → 수레-막대 환경 4096개 만들기 (물리 엔진: isaacsim_physx, 기준 실험과 동일)
150번 반복:
  1) 경험 모으기 (16걸음, 기울기 계산 없음)
     정책 신경망 → sample_action → 환경에 행동 → 점수·판 끝남 받기 → 저장소에 저장
  2) 마지막 상태 가치 계산 → compute_gae
  3) ppo_update
  4) 기록: 평균 총점, 평균 판 길이, 학습 상태 지표 → tensorboard
  5) 50번마다 신경망 저장
```

### 주의점 (코드에 설명을 달아둘 부분)
- **시간 초과로 끝난 판**: 수레-막대는 300걸음이 지나면 막대가 서 있어도 판을 끝낸다. 이건 "실패"가 아니라 "시간이 다 된 것"이라, 미래 점수를 0으로 보면 안 된다. `rsl_rl`과 같은 방식으로, 시간 초과 걸음의 점수에 `γ · V(지금 상태)`를 더해 보정한다. 그다음 `done = 실패 또는 시간 초과`로 이득 계산에 넘긴다.
- **점수 계산 방식**: `rsl_rl`과 똑같이 "최근 끝난 100판의 총점 평균"을 쓰고, 기록 이름도 `Train/mean_reward`, `Train/mean_episode_length`로 같게 해서 그래프를 겹쳐 볼 수 있게 한다.
- **행동 범위**: 정책이 뽑은 행동을 그대로 환경에 넘긴다. 범위를 자르지 않는 것도 `rsl_rl`과 같다.
- 실행 명령은 `python ppo/train.py --seed 1`이다.
- 학습 기록은 `logs/my_ppo/cartpole/<날짜_시간>_seed<번호>/`에 저장한다.

## 7. 설정값

`rsl_rl` 수레-막대 설정(`isaaclab_tasks/core/cartpole/agents/rsl_rl_ppo_cfg.py`)과 맞춘다.

|---|---|---|

| 처음 행동 퍼짐(표준편차) | 1.0 (상태와 무관한 학습 가능한 값) | 같음 |
| 잘림 범위 ε | 0.2 | 같음 |
| 가치 손실 계수 / 엔트로피 계수 | 1.0 / 0.005 | 같음 |
| 고치기 반복 / 미니배치 수 | 5 / 4 | 같음 |
| 할인율 γ / λ | 0.99 / 0.95 | 같음 |
| 기울기 최대 크기 | 1.0 | 같음 |
| 학습 속도 | 0.001 **고정** | **다름**. `rsl_rl`은 KL을 보고 자동 조절 |
| 가치 손실 자르기 | **안 함** | **다름**. `rsl_rl`은 함 |

다른 두 항목은 PPO의 핵심이 아닌 안정화 기법이라 처음에는 뺀다. 검사 코드는 통과하는데 학습 통과 기준을 못 넘으면, **학습 속도 자동 조절**부터 하나씩 추가하는 실험을 하고 DEVLOG 7장에 기록한다.

### PPO 학습 상태 지표 (tensorboard에 기록하고, 각 지표의 뜻은 DEVLOG에 설명)

| 항목 | 정상 모습 | 이상 신호 |

## 9. 작업 방식

1. **Claude가 먼저 준비**: `model.py`, `train.py`, `test_ppo.py`, `plot_compare.py`, 빈칸이 뚫린 `ppo.py`
2. **Claude의 사전 확인**: 프로젝트 밖(임시 폴더)에 정답 코드를 따로 만들어, 검사 코드와 `train.py`가 맞는지, 통과 기준을 넘는지 미리 확인한다. 사용자가 Claude가 만든 부분의 버그를 잡느라 시간을 쓰지 않게 하기 위해서다. **정답 코드는 사용자가 요청할 때만 보여준다.**
3. **사용자가 빈칸 채우기**: 데이터가 흐르는 순서대로 다 → 라 → 마 → 바
   - 빈칸을 시작하기 전에 Claude가 그 부분의 원리를 먼저 설명한다.
   - 사용자는 PyTorch 기초(텐서 만들기, 사칙연산, 간단한 학습 예제)를 알고 있다. 따라서 힌트에는 쓸 만한 PyTorch 함수 이름(`torch.clamp`, `torch.randperm` 등)까지 넣는다.
   - 하나 채울 때마다 해당 검사 실행 → 통과하면 다음 빈칸
   - 막히면 Claude에게 힌트 요청. **Claude는 정답 대신 단계별 힌트**를 준다 (방향 → 수식 설명 → 비슷한 예시 순서). 정답은 사용자가 명시적으로 원할 때만 준다.
   - 통과 후 Claude가 짧게 코드 리뷰 (더 나은 표현, 숨은 실수)
4. **학습 실행**: 씨앗값 3개 학습 → 비교 그래프 → 통과 여부 판정
5. **기록**: 오류·해결은 DEVLOG 6장, 학습 결과는 7장, 완료 표시는 3장

## 10. 위험과 대응
